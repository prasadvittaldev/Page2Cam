# Windows Tray App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `page2cam.exe` becomes a Windows tray app that loads stopped, keeps the "Page2Cam" camera listed with a standby picture, starts/stops/force-restarts the video engine as a child process, and shows a grey/green/amber/red health icon.

**Architecture:** One exe, three roles: tray (default on Windows), engine (`--engine`, today's app minus camera registration, child of the tray), standalone (`--standalone`, today's app; Linux always). The tray owns the virtual-camera registration and writes standby frames; a `writer` field in the shared-memory header hands frame writing to the engine once it produces output. The tray supervises the engine through the existing token-protected admin API and exit codes.

**Tech Stack:** Rust, `windows` 0.62, `tray-icon` + `muda` (or equivalent that builds in the cargo-xwin cross-build), Media Foundation virtual camera, NSIS.

**Spec:** `docs/superpowers/specs/2026-11-19-tray-app-design.md` (approved 2026-11-19).

**Prerequisite:** the crop plan (`docs/superpowers/plans/2026-11-19-webcam-crop.md`) is complete — its Tasks 3–5 (camera start-retry, leftover-process stop with ancestor protection and `force`, Frame Server recovery) are reused here.

## Global Constraints

- Windows-only tray; Linux keeps today's behaviour (= standalone); all Windows code `cfg(windows)`; workspace builds on Linux and in `cargo xwin`.
- Roles: `page2cam.exe` (tray) · `page2cam.exe --engine --camera-from-tray --admin-port <p> --parent-pid <tray pid>` with env `P2C_ADMIN_TOKEN` (token never on the command line) · `page2cam.exe --standalone`.
- Single tray: named mutex `Local\Page2Cam.Tray`; second launch signals the running tray (open control page if running, else show menu) and exits. `--standalone` refuses to start (message box) while the mutex is held.
- Exe uses the Windows GUI subsystem; `--standalone` calls `AttachConsole(ATTACH_PARENT_PROCESS)`; tray mode prints nothing to stdout.
- Shared memory: header field `writer: u32` (0 none, 1 tray, 2 engine), set only by the tray; the engine's sink writes only while `writer == 2`.
- Engine exit codes: 0 (normal), 75 (restart requested — not a crash), 76 (admin port bind failed — tray retries once with a new port), other = crash (auto-restart once; second crash within 2 min → red).
- Engine start timeout 30 s (→ red); Stop: `POST /api/quit`, wait ≤ 10 s, then kill the engine tree; engine exits when `--parent-pid` disappears (checked every 1 s).
- Health every 2 s from engine `/api/state.health` + PDH: red (engine unresponsive 5 s while started, unexpected exit, camera driver missing/out of date, start failed); amber (skipped > 2 % of output frames, webcam < 12 fps while on, webcam reconnecting, cut-out auto Fast, video CPU fallback, camera retrying, system CPU utility > 85 % or clock < 70 % of base); green; grey when stopped. Hysteresis: show after 6 s, clear after 10 s good. Tooltip ≤ 127 chars.
- Standby pictures: two 1920×1080 PNGs from `scripts/make-brand-assets.py` ("Page2Cam is stopped — start it from the tray icon", "Page2Cam needs attention — open the tray icon"), embedded, converted once to NV12 BT.709 (`p2c_core::bgra_to_nv12`), written ~1 fps while `writer == 1`.
- Tray state file `<config dir>/page2cam/tray.toml` (`tray_seen`); "Start with Windows" = HKCU `…\CurrentVersion\Run` value `Page2Cam` = `"<exe>"` (only source of truth).
- Updates: tray runs checks (15 s after start, every 6 h, honours `check_updates`) and the install flow; engine updater off when `--parent-pid` is given.
- Targets: tray < 1 % CPU and < 40 MB RAM while stopped.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; don't run app instances while the user's Page2Cam runs (the app stops other Page2Cam processes at start).

## Review Focus

1. **Start/Stop during a Teams call** — the camera never disappears; the picture switches standby ↔ live with no garbage frames (never two writers). Test in Task 1 (`engine_writes_only_when_handed_over`) and Task 5 (`handover_sequence`).
2. **Engine hangs on Stop** — killed after 10 s, tray back to standby, no orphaned Chromium helpers. Test in Task 4 (`stop_timeout_kills_tree` state-machine test) and Task 5 manual.
3. **Tray killed or crashes while the engine runs** — engine exits within ~2 s (parent gone), camera registration goes with the tray, no leftovers. Test in Task 2 (`exits_when_parent_disappears`).
4. **Health flapping** under borderline load — hysteresis holds. Test in Task 3 (`amber_needs_6s_and_clears_after_10s`).
5. **Second launch** (double-click while running, sign-in autostart + manual start) — no second tray, no second camera. Test in Task 5 (`second_instance_signals_and_exits` with an injectable mutex check).

**Files:** `crates/p2c-shm/src/layout.rs`, `crates/p2c-vcam/src/windows_cam.rs`, `crates/p2c-vcam/src/lib.rs`

**Interfaces:**
- Produces: `p2c_shm::Writer { None = 0, Tray = 1, Engine = 2 }`; `unsafe fn set_writer(base: *mut u8, w: Writer)`; `unsafe fn writer(base: *const u8) -> Writer` (header stays 64 bytes — take the field from `_pad`; `VERSION` stays 2 since old DLLs ignore it); `p2c_vcam::FrameWriter` — a mapping writer usable by both tray and engine (`open() -> Option<FrameWriter>`, `write_nv12(&Nv12Frame, time_ms) -> bool`, `base()`), split out of `WinVcamSink`; `WinVcamSink` gets a mode `CameraMode::Own` (today) | `CameraMode::FromTray` (no `Owner`, writes only while `writer(base) == Engine`).
