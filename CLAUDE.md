# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What Page2Cam is

A Rust desktop app that renders a live, interactive web page offscreen (embedded Chromium/CEF) and outputs it, with the user's real webcam as a movable picture-in-picture overlay, to:
- a **virtual camera** (Teams, Zoom, Meet...) and/or
- an **RTMP stream** (YouTube Live) with page and/or mic audio.

The operator drives it from a local **admin web page** (opened in the default browser): live preview, click/scroll/type into the page, PIP drag/resize, stream and audio controls.

The webcam can also be **cut out** (room removed, person over the page) with two ONNX models: Quality (Robust Video Matting) and Fast (MediaPipe selfie).

**Overlay layers** (titles, tickers, HTML infographics, pictures, videos, YouTube) are drawn over everything, the person included, by a second transparent Chromium page; agents create them over MCP, the operator manages them in the admin page's Overlays panel. **Agent kit:** 48 built-in parameterised templates (layer kind `template`, values change live without reload), user templates, saved looks ("scenes"), and a guide (playbooks for 24 user groups, how-tos) that reaches every agent through the `guide` tool, MCP resources/prompts, the MCP instructions and a Claude Code skill.

Design: `docs/superpowers/specs/2026-11-17-page2cam-design.md`, `docs/superpowers/specs/2026-11-18-webcam-cutout-design.md`, `docs/superpowers/specs/2026-11-22-overlay-layers-design.md`, `docs/superpowers/specs/2026-11-24-agent-kit-design.md`. Plans: `docs/superpowers/plans/`.

## Hard constraints (decided by the user)

- **Windows 11 and Linux only.** No macOS, no Windows 10.
- **No OBS dependency.** Own virtual camera: Linux `v4l2loopback`; Windows 11 `MFCreateVirtualCamera` + our COM media-source DLL.
- Page audio goes to the stream only, not into call apps.
- The user tests Windows builds on their own PC; Windows-specific code can only be compile-checked from this Linux box, so make failures self-explaining (logs, admin status).

## Setup (Linux dev box)

```sh
cargo install export-cef-dir --version =156.6.0+156.0.30   # must match the pinned `cef` crate
export-cef-dir --force $HOME/.local/share/cef                  # Linux CEF (~1.5 GB)
export CEF_PATH=$HOME/.local/share/cef                         # needed for every cargo build/test/run
sudo modprobe v4l2loopback exclusive_caps=1 card_label=Page2Cam  # virtual camera device, once per boot
./scripts/fetch-models.sh   # cut-out models + ONNX Runtime 1.24.4 (Linux .so, Windows DLLs) into third_party/, sha256-pinned
```

Windows cross-build (no Windows machine needed): `rustup target add x86_64-pc-windows-msvc`, `cargo install cargo-xwin`, `export-cef-dir --force --target x86_64-pc-windows-msvc $HOME/.local/share/cef-win`, plus `clang-cl` and `lld-link` on PATH (here they're shims in `~/.local/bin`: `clang-cl` → llvm-19 `clang`, `lld-link` → rustup's `rust-lld -flavor link`). **Use `CEF_PATH=$HOME/.local/share/cef-win` for Windows builds**; the Linux CEF dir fails with "cef_sandbox_win.h not found".

## Architecture

Data flow: CEF off-screen page (BGRA frames → `FrameSlot`; page PCM → `AudioRing`) and webcam (BGRA → `FrameSlot`; while the segmenter wants it (`Nv12Gate`) the cropped NV12 also goes to a latest-only `Nv12Slot`, which the segmenter scales from directly, BGRA otherwise; the segmenter publishes a model-size `Mask` (one byte per pixel + `EdgeRange`) to a `MaskSlot`, and the compositors upscale it to the drawn size: bilinear + `EdgeRange` LUT, or with refined edges a guided filter with the webcam as guide) → `Ticker` (fixed fps) composites (page or backdrop, PIP, then the overlay layers: a second, transparent CEF browser whose premultiplied frames go to `OverlayFeed.slot` / the GPU overlay `PageInput`, blended over everything while `OverlayFeed.active`) → `FrameSink`s: virtual camera, `PreviewSink` (admin JPEG preview), `StreamSink` (ffmpeg). Mic + page audio + overlay audio (as page sound) → `Mixer` → ffmpeg.

Crates (`crates/`):
- `p2c-core`: `Frame` (packed BGRA8), `FrameSlot` (latest frame only + `seq` counter for staleness), `AudioRing` (bounded 48 kHz stereo f32 FIFO that drops the oldest). Hand-offs use slots/rings, never unbounded queues, so slow consumers can't build lag.
- `p2c-segment`: cut-out. ONNX Runtime is loaded **at run time** (`ort` `load-dynamic`, api-24) from `runtime_dir()` (exe dir if it holds the library, else `third_party/onnxruntime/<os>` **in debug builds only**; release builds look only next to the exe, so `target/release/page2cam` on Linux has no cut-out unless the files are copied next to it), so nothing links at build time and the xwin cross-build is unaffected. `RvmEngine` (640×360 in, recurrent state carried and reset on size/engine change, DirectML preferred on Windows; the DirectML session runs its CPU-side nodes on 1 thread with spinning off, `dml_threads`) and `FastEngine` (256×144, CPU). `Segmenter` thread: disabled unless `Backdrop::needs_mask` (a cut-out style, the BlurredRoom full frame, or a box other than Room; Image/Colour/YouTube full frames are pages and get the mask through the cut-out style they force), processes each webcam frame once, `FallbackPolicy` switches Quality→Fast when inference is slower than `max(camera interval, 1/15 s)` for 10 s, then retries Quality after 60 s, doubling the wait after each further fallback up to 10 min (reset after 10 min of Quality keeping up; the note counts down; manual switch re-arms everything; auto switch never saved). RVM state is reset on size change, re-enable and webcam stalls >1 s; 10 failed inferences in a row reopen the engine. Model input is scaled with `scale_frame_straight` (alpha is data, not transparency); from an NV12 frame at least the model size it is built directly (`nv12_to_rgb_f32_nchw`: Y and U/V averaged per output cell, converted once, no BGRA intermediate).
- `p2c-compositor`: `compose()` (letterbox page + PIP) and `Ticker` (absolute-deadline pacing; always emits frames, black without a page; a failing sink is logged and doesn't block others). `PipLayout { visible, x, y, width, style }`: x/y are 0..1 positions inside a 2% margin (corners exactly 0/1), width is a fraction of the output width, height follows the webcam aspect. `OverlayStyle`: Box (opaque, ignores alpha), CutoutSmall (side margins, stands on the bottom edge, y ignored), CutoutFull (full height, bottom, x slides, width ignored); cut-outs alpha-blend the matte (the mask upscaled to the drawn size; refined edges: guided filter computed ≤960 px wide, then bilinear, `EdgeRange` LUT skipped). A cut-out style without a fresh matte draws the raw webcam as a Box (never a frozen cut-out); under a generated full frame (`Backdrop.hides_room`) that box is drawn blurred instead, note "cut-out not ready" (never the sharp room). Output frames are always opaque. It lives in `Arc<RwLock<_>>` and the admin page changes it live. The admin UI JS mirrors this geometry exactly. The PIP hides when the webcam slot hasn't changed for 1 s. `Backdrop { full, in_box, refined_edges, hides_room }` (shared like `PipLayout`, read each tick): `FullBackdrop` Page | BlurredRoom (webcam cover-scaled and blurred instead of the page; no fresh mask → everything blurred, person too; no webcam → the page), `BoxBackdrop` Room | Blur | Image | Colour behind the person in the Box (no fresh mask: Blur → whole box blurred, Image/Colour → raw room). Image/Colour/YouTube full frames are not backdrops: Chromium shows a generated page (the compositor sees Page with `hides_room`). Blur is recomputed only on a new webcam frame, at reduced resolution. Both paths draw backdrops: CPU here, D3D11 shaders in `p2c-d3d` (Windows GPU path); if those shaders fail to compile, Page/Room stays on the GPU and anything needing them is handed to the CPU compositor. `TickerStats::compose_note()` (`ComposeNote`: cut-out not ready, webcam off, backgrounds unavailable) feeds `Status.background_note`. Both producers redraw only when an input changed (`Changed`/`RedrawWhy`); the 30 s "output (CPU|GPU)" log line counts composites by cause (page, webcam, mask, layout, backdrop, overlay, other). A hidden PIP's webcam frames, masks and layout cause no redraws (the blurred room still follows the webcam). Overlay layers: `Ticker::spawn(…, overlay: Option<OverlayFeed>, …)`; each tick `TickInputs.overlay_on` (= `OverlayFeed.active`) and `TickInputs.overlay` (the CPU slot's frame, only while on); `Compositor::compose_with`/`is_unchanged_with` blend it last (premultiplied over, 1:1 or scaled to fit, cached), output stays opaque; the GPU producer (`GpuProducer::with_overlay(PageInput)`, built by `RecoveringProducer` and routed through `PageHolder::on_overlay_texture`/`upload_overlay_frame`) draws it with `ps_layer` (1:1) or `ps_sample` (scaled) and the premultiplied blend state; its change key includes the overlay input's `seq` while on (0 off). Measured 2026-11-23 on the laptop: 1080p overlay pass 0.026 ms median on the RTX 2000 Ada (budget 1 ms).
- `p2c-browser`: CEF. **CEF owns the main thread**: `main` must call `maybe_run_subprocess()` first (CEF re-launches the exe as helpers), then `run()` pumps `do_message_loop_work` on the main thread. Other threads use the `Send` `BrowserHandle` (commands over a channel): navigate, back/forward/reload, mouse/wheel/key input, `current_url()`. Device scale is fixed at 1.0. `on_paint` copies the full buffer. With an `AudioRing` set, page audio goes to the ring (and not to the speakers). CHAR key events carry the character in `windows_key_code` on Windows but the VK code on Linux (`key_code_for`). Switches `disable-renderer-backgrounding` and `disable-background-timer-throttling`: Chromium would treat the offscreen renderer as hidden (Windows gave it Idle priority and EcoQoS) and throttle its timers. `BrowserConfig.overlay: Option<OverlayBrowser>` creates a second, **transparent** browser (`background_color` 0, so frames carry premultiplied alpha; checked in the render test on GPU textures and CPU paints) in the same CEF instance and pump loop, at the configured size, with its own slot, `paused` flag, audio ring and texture callback (`TextureCallback`; shared textures only when the page is on the GPU); `BrowserHandle::overlay()` is its handle (commands carry a target; `shutdown`/`recreate_cpu` act on both). `set_size(w, h)` changes the view rect (`was_resized`), kept for a CPU recreate like the frame rate; `size()` reads it.
- `p2c-webcam`: nokhwa capture with **`default-features = false`** (its mozjpeg C dep won't cross-compile). MJPEG/YUYV/NV12 are decoded in pure Rust (`decode.rs`); `choose_format` takes NV12 over MJPEG at the same mode (no JPEG decode; the cut-out reads the NV12 directly). NV12/YUYV convert only the crop rectangle (MJPEG decodes in full, then crops); a full-frame NV12 twin is the camera buffer, moved. The 30 s "webcam measured" log line includes the capture conversion cost (p50/p95). `Camera` is `!Send`, so it's opened on the capture thread. `pick_camera` never returns our own output device (by canonical path or the "Page2Cam" name), which would create a feedback loop.
- `p2c-audio`: `Mixer` (per-source on/gain, clamp, silence fill; `with_overlay(ring)` mixes the overlay browser's sound as page sound: same on/off and gain), `Resampler` (linear), `MicCapture` (cpal; started only when the operator enables the mic).
- `p2c-stream`: `StreamController` runs ffmpeg: raw BGRA on stdin plus f32le audio over a localhost TCP socket that **we** listen on and ffmpeg connects to. Inputs use `-probesize 32 -analyzeduration 0`, otherwise ffmpeg stalls ~5 s probing real-time audio. Video/audio writers are paced threads. Status (connecting/live/error) is parsed from ffmpeg's stderr (`frame=` = live). `redact()` keeps the stream key out of logs.
- `p2c-admin`: axum on `127.0.0.1` (port 8765 or any free port), its own tokio runtime thread. Every request needs the per-launch token (`X-P2C-Token` header or `?t=`) **and** a `Host` of `127.0.0.1:<port>`/`localhost:<port>` (DNS-rebinding guard). It talks to the app only through the `Controls` trait (tests use a fake, so it doesn't link CEF). UI is a single file `ui/index.html` (no external resources). WebSocket `/ws`: binary JPEG preview out, JSON input in (0..1 preview coords → page px via `map_preview`). `normalize_url` refuses non-http(s)/file schemes. Background routes: `GET/POST /api/background` (`BackgroundDto`; a bad colour/link/name → 400 `{error}`, nothing changed; POST answers the choices as applied), `POST /api/background/image?row=full|box` (raw body, own 20 MB limit → 413, not PNG/JPEG/WebP by magic bytes → 415; selects that row's Image), `GET /api/background/image?row=` (preview), `GET /api/background/thumb[?link=]` (YouTube thumbnail fetched by the engine, so the UI loads nothing from outside), `GET /api/screens` (`ScreenDto` list; 501 `{error}` where capture is unavailable). `GET /bg/<per-launch id>/current.html` and `/bg/<id>/image` skip the token (unguessable id, Host still checked; CSP allows only inline styles, its own image and the youtube-nocookie embed). `Status` has `background`, `box_background`, `refined_edges`, `background_note`, `overlay_layers` (visible count), `overlay_on`. Overlay layers (`Controls: Overlays`; trait defaults answer "not available"): `GET /api/layers` (`{layers, kinds, presets, anims}`), `POST /api/layers` (add; 400 `{error}`), `POST /api/layers/<id>` (partial), `DELETE /api/layers/<id>`, `POST /api/layers/<id>/asset` (raw picture/video, 200 MB limit, 415 unless sniffed as PNG/JPEG/WebP/GIF/MP4/WebM), `POST /api/layers/clear`, `POST /api/layers/order` `{ids}`; templates: `GET /api/templates[?category=]` (`{templates, categories}`), `GET /api/templates/<id>` (full, 404), `POST /api/templates` (definition, `{from_layer}` or `{copy_of}`), `DELETE /api/templates/<id>`; scenes: `GET/POST /api/scenes` (`{name, include_background, include_webcam}`), `POST /api/scenes/<id>/load` `{mode: replace|add}` (`{added, skipped, notes, background_full}`), `DELETE /api/scenes/<id>`; blocking work in `spawn_blocking`. The UI's Overlays panel has Layers / Templates (gallery, generated param forms, New/Edit/Duplicate/Import/Export, live params form for a selected template layer, "Save as template" for html layers) / Scenes tabs. The overlay browser loads `/ov/<per-launch ov id>/scene.html` (`AdminServer.ov_url`; its own id, not the `/bg/` one): `scene.html`, `scene.js`, `state[?since=rev]` (204 while unchanged), `layer/<layer id>` (an HTML or template layer's page from `overlay_layer_page`, CSP `sandbox allow-scripts`), `asset/<stored name>`; no token, Host checked, unknown files 404; the scene's CSP allows only its own script.
- `p2c-vcam`: `open_default()` platform seam. Linux: `V4l2Sink` (YUYV via a hand-written `VIDIOC_S_FMT` ioctl; no bindgen/libclang). Windows: `windows_cam.rs` checks that the CLSID is registered in HKLM, runs `MFCreateVirtualCamera(...).Start()` on an MTA thread, and writes frames into the DLL's shared memory. The camera is optional at runtime: failure → status shows the error, app keeps running.
- `p2c-shm`: shared-memory protocol (`Global\Page2CamFrames`, seqlocked header + BGRA ≤1920×1080), BGRA→NV12/RGB32 with pitch and scaling, and the camera CLSID. Platform-free, unit-tested.
- `p2c-vcam-win-source`: the COM media-source DLL loaded by Windows' Frame Server service, **ported from smourier/VCamSample (MIT)**: IMFActivate → IMFMediaSourceEx + IMFMediaStream2, IMFAttributes forwarded via vtable macro (`attrs.rs`). It ignores the D3D manager (CPU samples), offers NV12/RGB32 at 1080p/720p, and shows a "waiting" pattern when frames are >2 s old. **The DLL creates the Global mapping** (a normal user process lacks the privilege; the app opens it, retrying each second). Logs to `C:\ProgramData\Page2Cam\vcam.log`. Must be registered from a folder the service can read (`install-camera.cmd` copies it to Program Files and runs regsvr32).
- `p2c-screen`: screen capture for the `screen` full-frame background. `list()` (monitors: id = display device name without `\\.\` e.g. `DISPLAY1`, 1-based index, physical size from `EnumDisplaySettingsW`, primary), `pick(id)` (empty/`primary` → primary, id or index), `Capture::start(id, max_fps, sink)`: Windows Graphics Capture (`CreateForMonitor`, free-threaded frame pool on its own D3D11 device, cursor included, Windows draws its yellow border), a thread polls the pool at most `max_fps` a second (frames only arrive when the screen changes), copies via a staging texture into a BGRA `Frame` (alpha forced 255); dropping it stops the thread. Elsewhere `list`/`start` fail with "screen capture is Windows-only for now".
- `p2c-overlay` (platform-free): overlay layers. `layer.rs`: `Layer { id, name, x, y, w, h (0..1 of the output, x/y = top-left), z, visible, opacity, enter, exit (`Anim`: none/fade/slide-left/-right/-up/-down), hide_after_s, content }`, flat JSON with `kind`: `title {text, subtitle, style, colour, background}`, `ticker {items, speed, style, …}`, `html {html ≤ 256 KB}`, `image {asset}`, `video {asset | url, loop, muted}`, `youtube {video, start_s, loop, muted}`, `template {template, params}`; presets `news`/`minimal`/`brand`; `validate` clamps geometry inside the output and names bad fields; `merge` applies partial changes (`id`/`kind` fixed, unknown fields refused, `null` resets, YouTube `link` → `video`). `set.rs` `LayerSet`: add (ids sanitised `a-z0-9-` and unique, else from name or `<kind>-<n>`; kind default geometry; shown and in front unless told otherwise; at most 32), update, show/hide, remove, clear (hide all), reorder (back to front), `tick` (auto-hide counted from showing), `set_asset`, `load` (all **hidden**: nothing appears by surprise after a restart; invalid entries dropped) / `save` (atomic), `state_json` (`{rev, layers}`, HTML left out, per-layer content version `v`; template layers carry their effective `params` and a params version `pv`, and `v` covers the template id + HTML), `layers_json` (adds `template_missing`), `layer_page`, `save_template`/`delete_template` (bump `rev` so layers reload), `scene_layers`/`load_scene` (replace or add; template-missing or file-gone layers skipped and named). Template layers: `template` must exist in the `TemplateLib` (`set_templates`; built-ins only by default), geometry defaults from its `rect` (`full_frame` → whole output), `params` checked by `Template::check_params`; `update` merges `params` partially (`null` → default), a new `template` starts from its defaults. `template.rs`: `Template { id, name, category, description, params: [Param {name, type, default, help, required, min, max, options, columns, max_items}], html ≤ 256 KB, rect, full_frame, example, update, builtin }`, param types text/longtext/number/bool/colour/choice/list/table/datetime/duration/url/asset (https or `data:image` ≤ 1 MB)/qr (`effective` turns it into `{text, n, d}` via `qr.rs` and the `qrcode` crate); every template also takes `theme` (brand/news/minimal) and `accent`; `RUNTIME_JS` (`templates/_runtime.js`, the `P2C` helpers: onParams, text/el (text only), every/stop, tween, num/fmtNum/fmtTime/when, svg/linePoints/donut, qr, code highlighter, theme CSS variables). Built-ins: `templates/<id>.json` + `.html` (48, categories basics/time/cards/lists/data/cta/calm/software), embedded by `build.rs` (`builtin::SOURCES`). `store.rs` `TemplateLib`: built-ins + user templates in `<data dir>/overlays/templates/<id>.json` (≤ 200, never a built-in id; `export` adds `format: page2cam-template/1`). `scenes.rs` `SceneStore`: `<data dir>/overlays/scenes/<id>.json` (≤ 100; layers + optional background/webcam JSON; their pictures/videos copied to `scene-<id>-…` names, kept by the start-up prune). `assets.rs`: stored copies named `<id>-<random>.<ext>`, recognised by magic bytes (PNG/JPEG/WebP/GIF ≤ 20 MB, MP4/WebM ≤ 200 MB by path), served only by those names. `scene.rs`: the host page (`SCENE_HTML`, `SCENE_JS`: polls `state` every 250 ms, rebuilds a layer only when its `v` changes, so tickers keep scrolling and videos keep playing; titles/tickers set as text, never HTML; HTML layers in `<iframe sandbox="allow-scripts" src="layer/<id>">` = opaque origin, no token, no top navigation; YouTube in the sandboxed youtube-nocookie embed), `SCENE_CSP`, `LAYER_CSP`, `layer_page`, `template_page` (runtime + params as `application/json` with `<`/`>`/`&` escaped + template HTML), `missing_page`; template frames get changed params by `postMessage({p2c:"params"})` when only `pv` changes, and again on their `load` event (no reload). `util.rs`: `parse_colour`, `normalize_colour`, `youtube_id` (moved from `background.rs`, re-exported there).
- `p2c-guide` (platform-free): what agents read, one source. `content/instructions.md` (the MCP `instructions`, ≤ 60 lines), `content/howto/*.md` (templates, scenes, layout, privacy, writing-templates), `content/playbooks/*.md` (24, header lines `title`, `group` creators/business/care/community/software, `aliases`, `prompt`, `args`; sections Background/Webcam/Graphics/Steps/Rules; one `add_layer {json}` per line, each checked by a test against a real `LayerSet`), embedded by `build.rs`. `topic(q)` (ids, aliases, then word-overlap fuzzy: "doctor" → telehealth), `index`, `catalogue`, `template_topic`, `resources`/`read_resource` (`page2cam://guide|catalogue|howto/<id>|playbooks/<id>|templates/<id>`), `prompts`/`prompt` (one per playbook + clear-graphics, save-look), `skill_files`, `docs_files` (`docs/agent-guide/`, kept in sync by `tests/docs_sync.rs`).
- `p2c-update`: update checks against GitHub Releases (`fetch_latest` via the system `curl`, which ships with Windows 10+), `parse_release` (needs `Page2Cam-Setup-<v>.exe`, `SHA256SUMS`, `SHA256SUMS.sig`), `verify_sums` (ed25519, public key `RELEASE_PUBLIC_KEY`), `download_verified`. The private release key lives only at `~/.config/page2cam/release-signing.key` (back it up; losing it means installed copies can no longer verify updates). `examples/release_key.rs` creates/signs.
- `p2c-proc` (process control, Windows+Linux): ancestor-aware stop of other `page2cam.exe` processes (`stop_others_for_tray` spares the tray and its parents), process-tree kill, named locks (`Local\Page2Cam.Tray` held by the tray, `Page2Cam.Engine` by the engine/standalone; `lock_held` probes them).
- `p2c-tray` (Windows tray, `win/` = shell, the rest platform-free and unit-tested: `state` Supervisor, `health`, `launch`, `menu`, `icon`, `standby`, `settings`, `update`). `page2cam.exe` on Windows with no role flag is the tray: single instance (a second launch signals the running tray), GUI subsystem (no console, log `page2cam-tray.log`), starts **Stopped** (nothing heavy running), owns the virtual camera (registration, retry, Frame Server recovery via `p2c_vcam::CameraOwner`) with a standby picture (stopped / needs attention, NV12 built at start), supervises the engine child, runs the update checks (so updates work while stopped). Menu: status line, "Version <x.y.z>", Start, Stop, Open control page, Force restart (kill the engine tree and every other page2cam process, re-register the camera, start again), "Update now to <v>" (installed; portable: "Download update <v>…") or else "Check for updates" (asks GitHub at once on a worker thread; balloon "up to date" or the error), Start with Windows, Allow agents, Quit.
- Roles of `page2cam.exe`: **tray** (Windows default), **engine** (`--engine --camera-from-tray --admin-port <p> --parent-pid <tray>`, token only in env `P2C_ADMIN_TOKEN`; renders, serves admin, never registers the camera, exits if the tray is gone), **standalone** (`--standalone`, and all non-Windows builds: old behaviour, own camera registration, attaches to the parent console, refuses to start while a tray runs; the tray ignores other args), **MCP bridge** (`--mcp` alone; `mcp_bridge.rs`).
- Agent control (MCP, `docs/agent-api.md`): `p2c-mcp` (platform-free) = hand-written JSON-RPC 2.0 (`initialize`/`ping`/`tools/list`/`tools/call`, protocol 2025-06-18, also 2025-03-26), the 46 tools with schemas and argument checks (8 for overlay layers: `list_layers`, `add_layer`, `update_layer`, `show_layer`, `hide_layer`, `remove_layer`, `clear_layers`, `reorder_layers` (kind `template` with `template` + `params`; a param `{"path": …}` is embedded as a data URI ≤ 1 MB); `guide` (answered by p2c-mcp itself, no backend); `list_templates`, `get_template`, `save_template`, `delete_template`; `list_scenes`, `save_scene`, `load_scene`, `delete_scene`; ids limited to `[A-Za-z0-9_-]`, `path` only on local drives, html ≤ 256 KB, base64 pictures ≤ 20 MB) (bad args → tool result `isError`), `redact()` on everything an agent sees; `resources/*` and `prompts/*` from p2c-guide, advertised in `initialize`; `offline(msg)` answers those and `guide` without a tray (the bridge uses it) (RTMP keys, `t=`, Bearer, `"token"`), over `trait Backend { call(agent, BackendCall) }`. The tray (`agent_server.rs`, std threads, platform-free) always listens on `127.0.0.1:8766` (else a free port): `/tray/agents` (Bearer tray token; GET panel data, POST `{allowed}`/`{reset_token}`) for the engine's `/api/agents` proxy (engine gets `P2C_TRAY_URL`/`P2C_TRAY_TOKEN` in its env), and `/mcp` only while agents are allowed (404 otherwise; Bearer agent token, Host and Origin checked; POST → JSON or 202; `Mcp-Session-Id` keeps the client name). `agent_backend.rs` `TrayBackend`: start/stop/force restart/update through the controller (waits for Running), pages written to `Documents\Page2Cam\pages\<sanitised>.html` and opened as file URLs, everything else via the engine API (5 s, uploads/backgrounds 30 s; partial overlay/audio/background merged with the current values, partial layer changes merged by the engine; layer answers leave the HTML out (`html_bytes`); template/scene calls go to the engine routes, `list_templates`/`get_template` fall back to the built-ins while stopped, a loaded scene whose `background_full` is `screen` gets the screen-sharing balloon; streams use the saved URL + key). `agents.rs`: discovery file `%LOCALAPPDATA%\page2cam\agent.json` (`{url, token}`, only while allowed), registration (Claude Desktop/Cursor `mcpServers`, VS Code `servers`, Codex `[mcp_servers.page2cam]` via toml_edit; only existing config dirs, atomic writes, unparseable files untouched; Claude Code only via `claude mcp add/remove --scope user`), the Claude Code skill (`apply_skill`: `<home>/.claude/skills/page2cam/` = `p2c_guide::skill_files()` + marker `.page2cam-skill` with the version; only if `~/.claude` exists; rewritten via a `page2cam.part` folder only when version or files differ; removed when agents are switched off; a folder without the marker is never touched), activity ring (200), balloons (start/stop/restart, streams, update; page/background changes while running; "is sharing your screen" for `set_background(full: screen)` always; none for layer changes, which are listed in the activity). `tray.toml`: `agents_allowed`, `agent_token`. Tray: "Allow agents" menu checkbox, blue badge on the icon and "Agent: <name> (active)" tooltip line for 60 s after a call. Bridge: reads tray.toml; agents off → local `initialize`/`tools/list`, every call "Turn on 'Allow agents'…"; no tray → starts it detached (`DETACHED_PROCESS|CREATE_NEW_PROCESS_GROUP|CREATE_BREAKAWAY_FROM_JOB`) and waits ≤10 s for agent.json; tray gone → re-reads agent.json and replays `initialize` once. stdout is JSON-RPC only; log `page2cam-mcp.log`. serde_json has `preserve_order` (agent configs keep their key order).
- Writer handover: the shared-memory header has a `writer` field (0 none, 1 tray, 2 engine), set only by the tray. The tray writes standby frames (~1 fps) while it is 1; the engine sink writes only while it is 2. The tray flips to 2 when the engine's `/api/state` says `output_ready`, and back to 1 on Stop/exit/crash/kill (standby resumes after a 100 ms grace), so two writers never touch the seqlock. The tray owns the `dll_version` check (red: driver out of date).
- Engine exit codes (`engine.rs`): 0 normal (user Stop, Ctrl-C, parent gone; stopped by itself = grey, no restart), 1 crash, 75 restart requested (GPU change; not a crash, more than 3 within 120 s -> Error), 76 admin port could not be bound (while starting; the tray retries with a new port), 78 started wrongly (no token; no retry). A crash restarts the engine once; a 2nd within 2 min -> red Error, stays stopped, notification. Stop = `POST /api/quit`, kill the tree after 10 s; Starting times out after 30 s.
- Health icon: grey (Stopped/Starting/Stopping), green, amber (CPU clock <70%, CPU busy >85%, output skipped >2%, webcam reconnecting/error/<12 fps, cut-out on Fast, video on CPU, camera retrying), red (Error state, unresponsive engine, camera driver out of date/not installed; immediate). Hysteresis: a worse level shows after 6 s of the same raw level, a better one after 10 s of continuous better readings (to the worst level in that window); a 15 s polling gap drops the timers. The tooltip lists the reasons.
- Tray state: `<config_dir>/page2cam/tray.toml` holds `tray_seen` (first-run balloon); the tray never writes the engine's settings. "Start with Windows" is the value `Page2Cam` under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` = `"<exe>"` (starts the tray, stopped); the Run key is the only source of truth. On the tray's first start (no `tray_seen`) it applies the installer's choice from `autostart.default` (`1`/`0` next to the exe; absent in the portable zip) to the Run key once (`settings::first_run_autostart`); afterwards the file is ignored, so reinstalling doesn't change the choice.
- `page2cam`: binary. `update.rs`: `Updater` (standalone/Linux; in engine mode the tray does the checks) checks 15 s after start and every 6 h (`check_updates` config), shows a banner in the admin page; installed copies (Uninstall.exe next to the exe) download+verify the setup and start it elevated with `/S /RELAUNCH`, then close. `overlay_style`/`cutout_engine` chosen in the admin page are written back to the settings file with `toml_edit` (comments kept). `background.rs`: full frame `page|image|colour|youtube|screen|blurred-room`, box `room|blur|image|colour`. Image/Colour/YouTube are generated pages (no scripts; YouTube = sandboxed youtube-nocookie iframe, autoplay, loop); Screen (`screen.rs`) is a black generated page whose paints are dropped (`BrowserConfig.paused`, shared `App.page_paused`) while `ScreenShare` runs a `p2c_screen::Capture` of the chosen monitor at `fps`, its frames going to the CPU page slot and, in GPU mode, `PageHolder::upload_frame` (`PageInput::upload_frame`, any size, letterboxed like a page); switching away stops the capture first, then resumes Chromium's paints with a repaint; a failed start leaves black and is the first `background_note`; setting `background_screen` (monitor id; empty = primary), `BackgroundDto.full_screen` served at `http://127.0.0.1:<port>/bg/<id>/current.html?v=<n>`, which Chromium navigates to (http, not file://, so the embed gets an origin); YouTube sound is page audio (stream only). Switching back to Page or Blurred room reloads `last_page_url`; the admin URL box keeps showing it, "(paused — background showing)". Admin navigation while a generated page shows switches back to Page. Interplay: Box with a full frame other than Page → full frame back to Page; a full-frame background chosen in Box → style `cutout-full`; both saved, with a 10 s note (a hand-edited Box + full frame is switched at start-up, logged and saved too). `last_page_url` follows the user's page while no generated page shows: admin navigation, and every shown-URL change the 250 ms watchdog sees (Back/Forward, the page's own navigations); written at most once per 2 s, never a `/bg/` or non-page URL. Back/Forward are ignored while a generated page shows; a watchdog (every 250 ms) loads `last_page_url` if history lands on a `/bg/` page, but only once history moved since our last `load_url`: a Back/Forward, or the shown URL changing from what it was at that load (the page's own `history.back()`); a slow load never changes the shown URL, so it is never reloaded. Uploads (≤20 MB, decoded one at a time with limits, scaled to ≤3840 px, re-encoded PNG if alpha else JPEG) are stored in `<data dir>/backgrounds/{full,box}.{png,jpg}`, one per row. Bad saved values fall back to Page/Room with a warning. Settings keys: `background`, `background_image`, `background_colour`, `background_youtube`, `box_background`, `box_background_image`, `box_background_colour` (colours `#rrggbb`, default `#0b63f0`), `refined_edges` (default false), `last_page_url`; a background change writes them together in one `save_values` call (`last_page_url` is also written alone as the page moves). Mic is delayed by the cut-out's inference latency (median of ~2 s) plus the output pipeline latency (`App.pipeline_ms`, from `Ticker::pipeline_latency_ms`; e.g. the GPU readback ring), capped at 250 ms (`Mixer::set_mic_delay_ms` keeps that much mic audio queued, rebuilt after resets/underruns) so lips match on the stream. `page_fps.rs`: `PageQuality` steps the page down a ladder of two levers, frame rate (`BrowserHandle::set_frame_rate`) and render size (`BrowserHandle::set_size`; both kept when the browser is recreated): (fps, 1920x1080) → (20, 1080p) → (15, 1080p) → (15, 1280x720) → (10, 1280x720) → (10, 960x540) (sizes are 1, 2/3, 1/2 of the configured size; rungs faster than `fps` are dropped, 30 is kept above it), one step down while the output skips more than 10 % of ticks for 3 s (one step per 10 s, the health window), back up one step per 30 s at ≤ 2 % skipped; fed by the 1 s health samples once output is ready, logged "page quality changed" (fps, size). The compositors scale the smaller page up; `App::input` rescales admin/agent page pixels (mapped at the configured size) to the rendered size (`scale_input`, wheel distances too). The overlay browser follows the frame rate only, never the size. The screen background is not the browser and is unaffected. `overlay.rs`: `OverlayLayers` (in `App.overlay`) owns the `p2c_overlay::LayerSet` (`<data dir>/overlays/layers.json`, files in `overlays/assets/`, unused files pruned at start), the `TemplateLib` (`overlays/templates/`) and the `SceneStore` (`overlays/scenes/`; `App::save_scene` adds the `BackgroundDto`/`PipDto` when asked, `App::load_scene` restores them after the layers and reports notes), saves after every change, ticks every 250 ms (auto-hide), and turns the overlay on/off (`decide`): on at once when a layer is visible (paints resumed with a repaint, page frame rate), off 1.2 s after the last one is hidden (exit animation done): paints dropped, 1 fps, `OverlayFeed.active` false (no overlay pass, no cost). `power.rs` (Windows; no-ops on Linux): the engine (or standalone) process opts itself out of power throttling (EcoQoS) at start, and a sweep 5 s after start, then every 30 s, opts out new descendants running our exe (Chromium helpers) or ffmpeg; priority classes are left alone. `onnxruntime.dll` needs the VC++ runtime: the zip ships `vc_redist.x64.exe` and `install-camera.cmd` installs it. Settings: `--config`, else `page2cam.toml` next to the exe, else `<config_dir>/page2cam/config.toml`; CLI overrides. Log: `page2cam.log` next to the exe on Windows (engine/standalone), data dir on Linux. The Windows manifest is compiled with `llvm-rc` in `build.rs` (lld can't embed manifests without `mt.exe`). `App` implements `Controls`. The stream key is optionally stored in the OS keyring (`keyring` v3) and never logged.

CEF test binaries use `harness = false` (libtest rejects CEF's helper-process flags), and CEF can initialize only once per process, so all render checks run as steps of one session.

## Installer

`packaging/windows/installer.nsi` (NSIS 3, amd64, per-machine, admin). NSIS runs on Linux from an unpacked Ubuntu package at `~/.local/share/nsis-pkg/root` (`apt-get download nsis nsis-common` + `dpkg -x`; override with `NSIS_HOME`); the build uses `-WX`. Native Windows makensis has no amd64 stub, so it can only check a copy of the script with the `Target` line removed. The installer stops page2cam (`taskkill /IM page2cam.exe /T /F` covers tray and engine) and the FrameServer services, moves a locked old camera DLL aside (deleted on reboot), installs vc_redist, regsvr32s the DLL, adds shortcuts (they launch the tray) and an Apps entry, and with `/RELAUNCH` restarts Page2Cam (the tray, no args, so Stopped) as the user via explorer.exe. Text says "Page2Cam waits in the tray until you click Start". The components page has the optional "Start Page2Cam (stopped) when I sign in" (default on; `/S` installs are on). The elevated installer can't reliably write the user's HKCU Run key, so it writes `autostart.default` (`1`/`0`) into the install dir before any relaunch, and the tray applies it to the Run key on its first start (see Tray state). Uninstall deletes the Run value of the elevated user (usually the same user; another user's value is left, and the tray removes nothing, so it then points at a missing exe and does nothing). Installed copies keep settings in `%APPDATA%\page2cam` (no page2cam.toml next to the exe) and logs in the user data dir. The zip stays as the portable option.

Branding: `assets/logo-source.png` (transparent) → `scripts/make-brand-assets.py` → exe icon (`crates/page2cam/windows/page2cam.ico`, embedded via page2cam.rc), installer images, admin `ui/logo.png`/`ui/icon.png` (served at `/ui/*.png`, token required). Admin theme colours: navy `#0d1b2a`, brand blue `#0b63f0`, white.

## Known open risks

- Refined-edges GPU cost (`gpu_refined_and_blur_within_budget`: the cut-out layer pass with refined edges on minus off, spec budget ≤ 2 ms) on the user's laptop, 2026-11-21: NVIDIA RTX 2000 Ada 0.05–0.12 ms; Intel UHD 0.3–0.9 ms, but 2.0–3.1 ms for the full-size cut-out (over budget; Intel only matters on machines without a faster GPU). The CPU compositor logs its cost in the 30 s output stats line ("refined edges …"); the admin UI shows no number, and the spec's "status line shows the cost when over budget" rule is not implemented yet.
- The user's laptop sometimes holds its NVIDIA GPU at P8 (210 of 3105 MHz, nvidia-smi "SW Power Cap" + "SW Thermal Slowdown"). Whole GPU frames then take 6–8 ms instead of ~2 ms, and a heavy WebGL page (e.g. Vanta clouds) saturates it: Chromium's GPU work starves the compositor and the output fell to ~1 fps. The engine now lowers the page frame rate, then its render size, while the output skips ticks (`page_fps.rs`); not yet measured against that page on the laptop.
- Agent kit: every built-in template is checked in the CEF render test (640x360 overlay, example params, a live update), but not yet in a full engine run on the laptop at 1080p; MCP resources/prompts and the Claude Code skill have not been tried in real agent apps; template looks were reviewed only through that test, not by eye.
- Overlay layers have been checked in the CEF render test (transparency on GPU textures and CPU paints, the real scene page with a title and a sandboxed HTML layer) and the GPU tests (blend parity, pass timing), but not yet in a full engine run on the user's laptop (the build agent may not start page2cam.exe): the idle pause, the GPU overlay texture path in the running engine, video/YouTube layers and their sound are unverified.
- The Windows camera DLL **works on the user's PC** (seen in Teams/Meet after running install-camera.cmd). Teams remote viewing (others in the call seeing it) is not yet confirmed.
- DirectML (GPU) for the Quality cut-out runs on the user's laptop (NVIDIA, ~13 masks/s with a 20 fps webcam), but stalls for seconds when the GPU is saturated (see above), and the fallback then switches to Fast. On the Linux dev box (Ryzen 5 8600G, CPU, release) Quality takes ~31 ms/frame (20–23 masks/s end to end), Fast ~1 ms.
- The webcam-mode choice (`choose_format`, aiming at ~30 fps) has never run against a real camera; the user's integrated webcam was reported as "1280x720@1".
- Linux v4l2loopback writing and webcam capture have never run against real devices on the dev box (no module loaded, no webcam).
